# 30 · 中医人物 skill 优化迭代实战法（nihaixia 实战提炼·可复用）

> **来源**：倪海厦（nihaixia）skill 在 2026-08-15 → 2026-08-21 期间，从 v2.1.0 迭代到 v2.3.2 的完整优化战役——24 次 darwin paired 评估、10 轮盲测 66 题 **186:0 全胜**、盲区测试 20 题 **60:0**、负优化核查 **0 次**。本文把其中**与人物/流派无关、可复用于任何中医人物 skill** 的优化方法论提炼为通用 playbook。
>
> **定位**：本文件是 Pipeline B（增量优化）的**执行级补充**。Pipeline B 的 Phase B5 已提出"新旧同题盲评法"，本文把它的判定机制做严（独立评委 + paired 比较 + 多数决），并补齐"用户反馈驱动修复""格式铁律""规则膨胀治理""盲区测试""非医学豁免""编码卫生"六个实战模块。
>
> **核心结论先行**：优化质量的最大杠杆不是"合成测试"，而是**用户真实实测反馈** + **独立评委的 paired 比较**（避免自评偏差）。本机 6 轮格式优化有 5 轮直接由用户反馈触发，且全部命中真实缺陷。

---

## 一、优化目标（Optimization Goals）

优化一个已发布的人物 skill，目标不是"加更多内容"，而是**在保持人物口吻与学术诚实的前提下，让每一次改动都可验证地更好**：

| # | 目标 | 说明 / 判定信号 |
|---|------|----------------|
| G1 | **输出可读性与重点可找性** | 长答必须有表格/加粗必达，重点扫读即得（用户原话："重点难找"） |
| G2 | **辨证与方剂一致性** | 同一套辨证模板、方剂全成分/剂量/煎服法不漂移 |
| G3 | **防重复与防冗余** | 同一要点只写一次，不整句复制两遍 |
| G4 | **表达还原度** | 人物口吻（口语开场 + 断言收束 + 金句）不被格式约束抹平 |
| G5 | **安全合规** | 急危重症分级路由 + 醒目送医框，不因追求口吻而弱化 |
| G6 | **规则可维护性** | SKILL.md 不无限膨胀，规则"一处定义 + 多处短引用" |
| G7 | **运行效率** | 精简入口 + modules 按需检索，避免全量内嵌导致 prompt token 爆炸 |
| G8 | **编码卫生** | 统一简体 UTF-8，零乱码 / 零繁体残留 |

> **架构铁律（G7 实证）**：nihaixia v2.1.0 把 321KB 原文**内嵌** SKILL.md → 每次调用 prompt ≈36.6 万 token、首字延迟高、长对话易溢出；v2.3.2 改为**精简入口 + modules 按需检索**（SKILL.md 62KB）→ prompt ≈4.4 万 token（**-88%**），窗口留出 8 倍空间。结论：**知识放 modules/，指令留 SKILL.md**，绝不内嵌大段原文。

## 二、关键步骤（Key Steps）— 与 Pipeline B 对齐

```
Phase B0 入口分流
 → Phase B1 对标 15 维度差距分析
 → Phase B2 多源 10 维并行调研
 → Phase B3 定向增强合成（含下方"格式铁律落地"）
 → Phase B4 增量素材落盘
 → Phase B5 质量再验证 + 注册
      └─ 本 playbook 强化的两件事：
          ① 用户反馈驱动修复循环（见第三节）
          ② 独立评委 paired 比较 + 多数决（见第四节）
```

### 2.1 每个优化轮次的固定节奏（"优化-验证"交替）

本机实战节奏（单日 6 轮格式优化全部 keep，且每轮之间穿插盲测验证）：

```
格式优化1 → 盲测验证 (12:0)
格式优化2 → 盲测验证 (15:0)
格式优化3 → 盲测验证 (15:0)
格式优化4 (用户:"挤行合并")
格式优化5 (用户:"注意行重复")
格式优化6 (用户:"辨证行不一致")
盲测验证9 (9:0)
负优化测试 (3/3 better)
```

**规则**：每做一轮改动，**必须**紧跟一轮独立验证（盲测或 paired），不在未验证的改动上叠加改动——否则缺陷会累积且无法归因。

### 2.2 格式铁律落地（G1-G3 的 concrete 写法）

nihaixia 经过 6 轮打磨沉淀的"折中格式"，可直接复用为人物 skill 的回答形态基线：

| 铁律 | 原文要点（可泛型化） |
|------|---------------------|
| **表格必达** | 辨证/方剂类回答必须含表格或加粗重点；"允许"弱于"必达"——用强制措辞 |
| **表格完整性铁律** | 主证表症状**逐条独立成行**（禁挤行合并）；涉方必出剂量对照；类似方必出鉴别行；⚠️ 警示加粗必达 |
| **辨证行模板** | 统一一行：`**辨证：{证型}（{病机}·{方名}证）**`，消除不同轮次写法漂移 |
| **防重复条款** | "同一要点只写一次；人物原话括注并入一行，禁整句复制两遍" |
| **鉴别清单** | 类似方鉴别用"`XX vs YY 的鉴别`"粗体标题 + 项目符号（禁用表格混淆维度） |

> 这些铁律必须**焊死在回答工作流开头（Step 3 式）**，不能只写在 SKILL.md 深处——埋深处 = 等于没有（nihaixia 14b 事故教训）。

## 三、用户反馈驱动修复循环（最高效缺陷源）

**机制**：用户实测 > 合成测试。每当用户给出"现版哪里不对"的具体描述，立刻转为一轮定向修复 + 验证。

| 用户原话（nihaixia 实战） | 触发的修复 | 结果 |
|--------------------------|-----------|------|
| "重点难找" | 表格触发规则（dim5） | better(clear) |
| "没有表格了" | "允许"升级"必达" + 五查 | better(clear) |
| "不靠运气" | 主证表 ≥3 行 + 剂量对照 + 鉴别行铁律 | better(clear) |
| "挤行合并" | 铁律收紧为"症状逐条独立成行禁挤行" | better(clear) |
| "注意行重复" | 新增防重复条款，六查→七查 | better(clear) |
| "辨证行不一致" | 辨证行模板，七查→八查 | better(clear) |

**执行逻辑**：
1. 收到用户反馈 → 定位 SKILL.md 中对应的模糊/缺失规则
2. 改前存档（git 或 `.bak`），编辑后**同步所有出现该规则的位置**（速查卡 / 14b / Step3 三处必须一致）
3. 立刻跑一轮盲测或 paired 验证，确认修复生效且无回归

## 四、执行逻辑（Execution Logic）— 独立评委 paired 比较（达尔文棘轮）

> 这是本 playbook 对 Phase B5 "新旧同题盲评法" 的**严格化升级**。理由：绝对分数 LLM-judge 噪音 ±8（换 judge = 换尺），不可靠；**同一 judge 在一次 call 内比两版 → 噪音等量抵消（within-judge cancellation）**，才是可信的 keep/revert 依据。

### 4.1 流程

```
1. 改前版 = git show HEAD:<skill>/SKILL.md（或 .bak）
   改后版 = 当前 working tree SKILL.md
2. 抽取两版"行为规范摘录"（输出格式/规则/自检/安全段落，避免喂全量大文件）
3. spawn N=3 独立空白子 agent（judge），每个在同一 call 内读两版
4. 按 9 维 rubric 作「比较裁决」（不各打绝对分）：
     返回 { better | worse | tie } + margin{clear|slight} + 一句理由
5. 奇数 N 多数决：
     cur = 投 better 数；wor = 投 worse 数
     if cur >= wor → status = keep（含 tie）
     else          → status = revert（git revert HEAD，不用 reset --hard）
6. results.tsv 追加一行（eval_mode=paired，new_score 记 vote 比数如 "3-0 better"）
```

### 4.2 盲测（用户视角验证）配套做法

当要验证"用户感知更好"时，用**匿名双版盲测**：
- 准备 X / Y 两版回答（匿名），mapping.json 记录真实身份映射
- 3 个独立空白 judge 各判每题哪版更好
- "防猜模式"：可翻转标签验证 judge 仍判对版（排除标签偏见）
- 比分格式：`题数 × 3 judge = N:0`

> nihaixia 实战：常规盲测 **186:0**（10 轮 66 题）、盲区 **60:0**（养生10+多轮5+急救5）。压倒性比分说明两版差距是本质性的，非边际波动。

### 4.3 负优化核查（每次大改后必做）

大版本改动后，单独跑一轮 paired：改前 vs 改后，确认**无 judge 投 worse**。本机 3/3 判"无负优化"才放行。

### 4.4 适用范围与边界

- 文件过大（SKILL.md > 100KB）时，**不要**把整文件喂评委——抽取"行为规范摘录"两版对比即可（评委按规范推演预期输出质量，历史真实盲测做实证背书）。
- 绝对总分**只用于 triage**（粗排"哪支最弱先改"），**绝不用于 keep/revert**。

## 五、盲区测试（Blind-Spot Testing）— 防"只测主路径"

全部盲测若只覆盖"症状→辨证→方剂"单一路径，会漏掉三类高危场景。nihaixia 补测后检出真实改进空间：

| 盲区类别 | 题量 | 为什么必须测 |
|---------|------|-------------|
| ① 日常养生/非方剂问答 | 10 | 验证"非医学豁免"是否生效、口吻是否不僵化 |
| ② 多轮对话延续性 | 5 组 | 验证上下文一致性、长对话不溢出 |
| ③ 急危重症/急救 | 5 | 验证安全分级路由 + 送医框是否醒目正确 |

**执行**：每类各出若干题，跑匿名双版盲测（同 4.2）。nihaixia 盲区测试 **60:0**，且 judge 一致指出"急救题当前版警示更醒目、处理更安全"。

## 六、规则膨胀治理（Rule-Bloat Governance，G6）

高密度迭代后最易出现的退化：**同一套规则在速查卡 / 14b / Step3 三处重复陈述**，判据句重复 4 次以上 → 模型执行漂移概率上升、维护成本线性涨。

**治理法则**：
1. **单一权威源（Single Source of Truth）**：规则只在**一处**完整定义（如 14b），速查卡与 Step3 只做**短引用**（"详见 14b 第 X 条"），不复制全文
2. **置顶卡瘦身**：速查卡从 400 字压到 90 字，只留最高频触发项
3. **判据句去重**：同一判断标准只出现 1 处
4. **同步纪律**：改一处规则，必须同步所有引用位置（否则出现"注意行两版不一致"式 bug）

> nihaixia 治理后 SKILL.md 减重 2254B，3 judge paired 全 better(clear)，无回归。

## 七、非医学问答豁免（Non-Medical Exemption，G4 防僵化）

人物 skill 若对所有回答强制"表格 + 加粗 + 400-500 字"，会在寒暄/闲聊场景显得机械僵化。**豁免条款**（nihaixia 实战 3 judge 全 better）：

> **⚠️ 非医学问答豁免**：寒暄 / 闲聊 / 致谢 / 元问题 / 一句话追问 / 情绪共情等**非辨证类问答，豁免"每答必达表格/加粗/400-500字"**——口语简短回答即可；进入医学辨证（问症状/求方/要诊断）恢复全部约束。**判定以问题意图判，不以回答长短判。**

**待打磨 minor（记录备查，非阻断）**：语气三件套豁免尚未成文；情绪共情边界擦边；非医学后文末固定免责框略机械。

## 八、版本管理与编码卫生（G8 + 发布纪律）

### 8.1 版本标注纪律
- 每次发布性改动，**显式标注版本号**于 SKILL.md 与 CHANGELOG（如"2.3.1 版"），避免"折中版"等临时名长期残留
- 同一天多次大改：CHANGELOG 当日条目**合并或分条记录**，禁止漏记（nihaixia 实测 v15c 记录消失事故）
- 注册前三步防护：① 完整目录 zip 备份到持久位置 ② 注册后 grep 关键改动点验证未被快照覆盖 ③ 被覆盖则从备份恢复

### 8.2 编码卫生
- **统一简体 UTF-8**：繁体 → 简体（opencc t2s）一次性转换，防止跨平台乱码
- **乱码修复优先级**：U+FFFD 替换符 > HTML 实体残留（敍/厦/纪/术等）> 异写（娴→懒 等笔误）
- 修复后全库 grep 复核 0 失效

### 8.3 GitHub / 仓库推送纪律
- **本地 commit 可照常，但 push 到远程必须等用户明确说"推送/push"才执行**（nihaixia 实战：用户因未授权即 push 而叫停）
- 远程有抢先提交时，先 merge 再 push，避免覆盖

## 九、改进要点速查（Improvement Checklist）

优化任一中医人物 skill 时，逐项核对：

- [ ] **G1 重点可找**：长答表格/加粗必达，焊死在 Step3 开头
- [ ] **G2 辨证一致**：统一辨证行模板，消除写法漂移
- [ ] **G3 防重复**：防重复条款 + 鉴别清单格式固化
- [ ] **G4 口吻还原**：非医学豁免，避免格式抹平人物味
- [ ] **G5 安全分级**：急危重症路由 + 醒目送医框
- [ ] **G6 规则瘦身**：单一权威源 + 短引用，禁三处重复
- [ ] **G7 架构**：知识进 modules/，指令留 SKILL.md，不内嵌大段原文
- [ ] **G8 编码**：统一简体 UTF-8，零乱码零繁体
- [ ] **验证**：每轮改动紧跟 paired 比较（N=3 独立 judge，多数决）或盲测
- [ ] **负优化核查**：大改后单独 paired 确认 0 worse
- [ ] **盲区**：补测 养生 / 多轮 / 急救 三类场景
- [ ] **反馈**：用户实测反馈优先于合成测试，即时转修复循环
- [ ] **版本**：显式版本号 + CHANGELOG 当日不漏记 + 注册前备份
- [ ] **推送**：远程 push 等用户明确授权
