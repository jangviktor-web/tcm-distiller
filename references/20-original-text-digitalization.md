# 原文数字化与行号索引方法论（A级沉淀·源自黄元御V2.9实战）

> 适用：蒸馏产物收录大部头原文（医书合集/讲稿全本/经典全文）时，将"大文件 → 可检索的行号索引体系"。源自黄元御 skill 的 3.5MB/38,266 行医书十一种全本处理实战（2026-08-04），全部步骤经过验证。
> **V4.1 补充**：编码统一规范（源自 wujutong GitHub Pages 构建失败教训——modules/00_index.md byte 2611 处 GBK 乱码残留）。

## 〇、编码统一（V4.1 新增，收录原文第一步）

- 源文件统一转 **UTF-8**：`iconv -f GBK -t UTF-8 input.txt > output.txt`（或 GB18030）
- **校验无乱码残留**：`grep -Pn '[\x80-\xff]' 文件 | head` 检查非法字节（wujutong 实测：GBK 残留乱码导致 GitHub Pages 构建失败）
- 转换后全库 `file` 命令抽查编码声明一致
- OCR 文本注意繁体/异体字保留（勿强行简繁转换，检索会失配）

## 一、为什么需要（问题背景）

- 原文文件动辄 3-8MB、数万行，AI 无法全文读入上下文
- 直接 match/grep 大文件：检索慢、命中噪音多
- 引用原文时无法给出精确出处 → 回答可信度低

**方案**：为原文建立"行号索引路由表"——书目总览 + 关键词速查 + 逐篇目行号，AI 先 match 索引（KB 级）→ file_read offset 读取 80 行，检索提速数量级、引用可溯源。

## 二、核心工作流（四步）

### 步骤 1：标题提取（分三级）
```python
# 提取规则（黄元御实战验证）
H1_RE  = ^# (?!#)(.+)          # 一级：书/卷标题
SEC_RE = ^#{2,4} (.+)          # 二~四级：卷/篇目标题（含四级！难经各难是 ####）
```
- **支持 2-4 级标题**：部分古籍篇目是四级标题（如难经"#### 二难"），只抓 2-3 级会漏
- **卷标特例白名单**：个别卷标是三级（如"### 四圣心源卷二·六气解"），需白名单识别，否则整卷从索引消失
- **噪音过滤**（必须，否则索引膨胀）：
  - 标题含句读（。，；）→ 正文误标
  - 标题 == 书/卷名 → 页眉（"金匮悬解卷一"重复出现）
  - 以"·"开头 → 页眉残片；含拉丁字母 → OCR 乱码
  - "X划" → 书末笔画索引；纯数字 → 页码

### 步骤 2：索引生成（三层结构）
```
索引文件 = 书目总览表（书/起止行/卷数/提要）
         + 关键词速查表（高频病证方药 → 书·篇·行号）
         + 逐书篇目索引（卷表 + 每篇目带 L行号）
```
- 书边界：`# 书名` 一级标题，结束行 = 下一本书起始行 - 1
- 篇目归属：按行号落在哪本书/卷范围内（勿依赖提取时的上下文变量，易被卷标覆盖）
- 同名篇目去重：目录页复述 vs 正文，保留行号最小的

### 步骤 3：行号全量校验（防漂移关键）
```python
# 校验规则：索引每条 `Lxxxx` 行号 → 读源文件该行 → 必须是以 # 开头的标题且标题文本一致
# 卷表行号同理校验
```
- **校验必须为 0 错误**才能注册
- 源文件任何清理/插入后，**必须重新提取+生成+校验**（行号会整体偏移）

### 步骤 4：检索路由接入
- SKILL.md 头部加"⚡快速检索路由"：问原文 → 先 match 索引 → file_read offset=行号-5, limit=80
- **明确禁止直接 match/file_read 大文件全文**（这是响应慢主因）
- 关键词速查表行号：**必须由脚本从源文件自动定位**（grep 标题），禁止手工 hardcode（黄元御实战教训：手工速查表 45 条行号 100% 漂移）

## 三、OCR 噪音清理流水线（清理顺序，按黄元御实战）

| 顺序 | 噪音类型 | 清理方式 | 量级参考 |
|------|---------|---------|---------|
| 1 | HTML 残留（`<div>`/页码容器） | 去标签；纯页码行删行 | 196 处标签 |
| 2 | OCR 页码混入（【102】等） | 正则删除 `【\d+】` | 1048 处 |
| 3 | 书名页眉混入正文（"内经是解卷X"） | 删除 `[☑■☐]?书名卷[一二三...]` | 400+ 处 |
| 4 | "#####"乱码页眉行 | 整行删除 `^#{2,5}` 且内容为乱码 | 213 行 |
| 5 | 【X医书十一种 第N页】页眉 | 删行/删串（OCR 把书名识别成各种变体，用宽模式"第N页"匹配） | 60+ |
| 6 | 纯"#"残留行 | 删除 `^#+\s*$` | 32 行 |

**⚠️ 最大坑（黄元御血泪）**：清理页眉的正则**必须区分真实卷标与页眉**——同一格式"金匮悬解卷一"，`# ` 一级是真卷标（保留），`###/####` 级是页眉（删除）。黄元御实战中误删了 56 处真卷标 + 丢失 18 处，需反推恢复。**清理前先备份源文件，清理后立即核对卷标数**（106 卷应完整）。

## 四、维基文库对照校对法（OCR 讹字修复）

适用：有维基文库/其他版本可对照的古籍。黄元御实战用此法修复 40+ 处讹字。

```
流程：上传对照件（HTML/txt）→ 解析为 篇目→正文 结构
     → zhconv 繁体转简体（pip install zhconv）
     → 逐篇对比：①首句（性味归经）一致性 ②正文长度差异>35% ③首处差异上下文
     → 输出差异清单 → 人工甄别（版本差异 vs OCR 讹字）
```
- **匹配键**：简繁归一后的篇目标题（勿用原始字，繁简/异体会失配）
- **甄别规则**：
  - 长度差异大 → 先查是否为页眉分隔导致的解析误报（如"### 长沙药解"页眉切断条目）
  - 首句一致+长度差小 → 多为版本排版差异（注文交错），非错误
  - 同位置单字差异 → 大概率 OCR 讹字（梦丝→棼丝、颅颡→颃颡、痎疟、瘿瘤……）
- **高频讹字模式**：形近字（腨/膈、疖/疗、疔/疗）、书名 OCR 变体（黄元御→董元御/黄云御/黄元淑）、页码混入
- **简繁转换**：对比前必须 norm（zhconv 转简体 + 去标点空白），否则全是"差异"噪音

## 六、执行要点速记

1. 提取支持 2-4 级标题；卷标特例用白名单
2. 噪音过滤宁可多收不可漏（页眉/乱码会污染检索）
3. 行号校验 0 错误是注册前提
4. 速查表行号必须脚本自动定位，禁手工
5. 清理页眉前备份；清理后核对卷标数
6. 源文件任何改动 → 重建索引 → 重新校验
7. 维基对照用 zhconv 简繁归一，甄别版本差异 vs OCR 讹字
