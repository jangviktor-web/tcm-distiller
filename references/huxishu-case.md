# 案例：胡希恕38万字讲稿蒸馏全记录

> 本案例是 tcm-distiller 工作流的实战验证。
> 素材：胡希恕《伤寒论与金匮要略》讲座完整讲稿（中日录音增补版），38万字 Markdown
> ⚠️ 注：下文 V1.0~V2.2 是**胡希恕skill自身**的版本史，与框架（蒸馏器）的 V2.x 特性编号无关。

## 迭代历程

```
V1.0 (初次注册)        12KB    SKILL.md 60行 + refs 5个
    ↓ 用户："缺失了什么"
V1.5 (补全压缩丢失)    31KB    SKILL.md 60行 + refs 5个重写
    ↓ 用户："参考倪海厦架构完善"
V2.0 (对标重建)       2.0MB    SKILL.md 304行 + modules/1.9MB + refs 31KB
    ↓ 用户："补充饮食调理"
V2.1 (饮食模型)       2.0MB    SKILL.md 304行 + refs 06-diet-wellness.md
    ↓ 用户："补充剂量+条辨框架"
V2.2 (剂量+框架)      2.0MB    SKILL.md 304行 + refs 07-dosage-framework.md
```

## 关键教训

### 教训1：子Agent产出别压缩
- **现象**：5个子Agent产出 ~50KB，写入 references/ 时被压缩到 12KB（注：当时框架为 5 维，现行 9 维）
- **后果**：心智模型、决策规则、表达DNA全部变成摘要，细节全丢
- **修正**：重写 5 个 references 文件，保留完整原文

### 教训2：必须对标倪海厦架构
- **现象**：最初 SKILL.md 只有 60 行，没有 modules/
- **后果**：缺乏诊断公式、方证鉴别表、原文检索能力
- **修正**：对照倪海厦 skill 补齐所有缺失组件

### 教训3：YAML 头部缺失
- **现象**：第一次注册报 411003 错误
- **修正**：添加 `name:` + `description:` 的 YAML frontmatter

### 教训4：增量补充模式
- 每次用户提出新维度（饮食/剂量），用 shell 搜索讲稿 → 提取 → 公式化 → 写入 → 重新注册
- "搜索→提取→公式化→注册"四步循环

### 教训5：每次修改都要重新注册
- 修改文件后不重新 `ima_skill_create`，用户下载的还是旧版

## 胡希恕特化发现

### 他讲稿中高频概念
| 概念 | 出现次数 | 说明 |
|------|:------:|------|
| 津液 | 784 | 最高频！超过胃气 |
| 胃气 | 222 | 核心中的核心 |
| 饮食 | 104 | 辨证指标 |
| 能食 | 114 | 判断胃气存亡 |
| 不能食 | 73 | 判断胃气衰败 |
| 谷气 | 81 | 津液来源 |

### 他的独特性
1. **"六经来自八纲"** — 对传统《内经》解伤寒的根本颠覆
2. **"方证是辨证的尖端"** — 他把辨证推到方证层面，不能停在"清热""解表"
3. **"阳=津液"** — 对《伤寒论》中"阳"字的独特解释（有争议）
4. **对经典的强烈批判** — 毫不客气地说欲解时"不可信"、五行"不是张仲景写的"
5. **诚实边界突出** — "没经验过""这也是个问题""我说这不是张仲景写的"

## 可复用的模式

### 1. 搜索→提取→公式化→注册
每次补充新维度都遵循这个模式。适用于任何中医师。

### 2. 七步条辨法
胡希恕分析条文的固定模式可以推广到其他经方派中医师。

### 3. 三个痛风方鉴别表
```
桂枝芍药知母汤 vs 乌头汤 vs 甘草附子汤
```
这种三栏对比表可以直接套用到任何类似方证的鉴别上。

### 4. 饮食调理公式
"损谷则愈""食复""饮酒禁忌""病后三禁"——这些公式有普遍适用性。

### 5. 技能增量模式
初始注册 → 用户反馈 → 搜索讲稿 → 提取新维度 → 补充注册。不需要一次性完美。
